# Windows qualification native components — incomplete integration

These components are qualification infrastructure only. They do not authorize a paid run, Claim, Provider request, Human Review, Runtime or Production. No installation, account creation or target provisioning is included.

## Build and safe local protocol check

From the EduFlow application directory, `./native/qualification/build-user-mode.ps1` builds collector, broker, observer-service, cleanup, protocol-tests, security-tests and observation-tests executables plus the Node-API 8 `bridge.node` into `.tmp/qualification-native-build`. It uses installed MSVC, a temporary compiler environment, workspace-contained output and `/W4 /WX /GS /guard:cf /sdl`, DEP and ASLR. Run only `protocol-tests.exe`, `security-tests.exe` and `observation-tests.exe` for ordinary local checks. `-SecuritySanitizer` builds the security and observation tests with installed MSVC AddressSanitizer. The protocol and observation tests create no qualification subject; observation tests use synthetic events and bounded in-process contention. The security tests also use a fixed nonprivileged helper to verify process-generation and exit-code-259 handling. No build step launches collector, broker, cleanup, service, privileged role or driver.

The user-mode build requires the Windows SDK. The minifilter separately requires WDK kernel headers and tools, which were unavailable during this implementation. No kernel build, signing, installation, load or real component laboratory verification is claimed.

## Boundaries and outstanding integration

- **Collector:** fixed INSPECT request through authenticated local IPC. Wire v4 requires separate primary and effective tokens, session/mandatory/UIAccess/virtualization context, token-profile fingerprints and separate primary/effective access masks. It also carries ancestor, volume/device/cache/filter, mandatory-label and PSS handle metadata. Token replacements/modification identities are checked again after object collection. `AccessCheck` and two handle snapshots do not prove complete ownership, privilege, MIC, storage or handle-lifetime authority. Those acceptance arguments remain open.
- **Bootstrap/bridge:** a read-only HKLM bootstrap and machine-protected configuration bind peer SID, image, PID/creation, fixture/profile/epoch/boot and reviewed files. One-shot named pipes authenticate both peers and use a bound receipt to keep senders alive during verification; no stdout or caller-selected path is authority. The Node-API bridge verifies its actual image and fixed Node command/cwd and uses no `.tmp` fallback. Sampled loaded modules must belong to the exact sealed file list. The JS required-fact gate currently blocks every wire-v4 observation, including authenticated ones: full storage, composite access, retained-handle lifetime and runtime/dependency closure cannot yet be proven. Its bounded rights diagnostics do not grant provenance or authority. Missing required facts cannot be replaced by caller flags, hashes or empty inventories.
- **Observer service (QI-B2):** B/v2 dialect, fixed local pipe and filter port, protected process-generation/image/SID/module checks, full request binding and one-shot commands. Native ETW session queries, initial fixed-target thread census, exact DCStart-generation matching and one-use census confirmation implement a target-rundown barrier. This is not global volume/object coverage. Complete volume/device resolution, effective-token/retained-object continuity and A evidence resolution remain missing. Final kernel health is read after ETW stop/join; a separate authenticated EOS acknowledgement precedes a complete receipt. Unexpected disconnect remains fatal. No successful complete observation or authority is currently reachable through the service because the global kernel coverage gate remains blocked. Source compilation and deterministic reducers are not live ETW verification.
- **Minifilter (QI-B2):** B/v2 audit-only source uses a shared locked state machine, volume cache, per-open file-ID/stream cache, pre/post queue, generation/token IDs, zero-byte create outcomes, writes/truncates, security masks and cleanup/close records. B2 adds shared bounded decoders for ordinary/extended rename/link/disposition and Microsoft junction/symlink reparse set/remove input. The fixed peer is read from a machine provisioning value, not caller arguments. Complete trusted bootstrap/volume coverage, actual rename/link destination/replacement identity and alias transitions, full reparse resolution, retained objects, impersonation, directory coverage and kernel race/lifetime validation remain incomplete. Missing global coverage sets a sticky block when capture starts. Successful unresolved rename/link also blocks in the service reducer. Unsupported contexts/operations block evidence; subject I/O always continues. This is **not deployable or qualified** source.
- **Launcher/controller client:** the public fixed-role entry is blocked in this build because complete release closure is unavailable. The retained suspended-launch implementation binds external ticket redemption, fixed image/token/handle checks, independently signed acknowledgements and exit recording. No arbitrary command, credentials, shell or executable comes from a JS request. The authenticated external server, qualified persistence and complete observer barriers remain missing; compilation and synthetic protocol tests do not prove actual role isolation.
- **Cleanup:** a separate executable reads an exact sealed disposable manifest. External evidence/consumption/intent acknowledgements precede target opens with DELETE rights. Handle-relative existing-object opens, object/device checks, exclusive selected handles and child-before-parent order constrain deletion. It never walks a reparse target, enumerates recursive deletion candidates, resets consumption, repairs ACLs or deletes a caller-selected path. Each destructive step requires a fresh authenticated journal acknowledgement and records its outcome; uncertainty stops. This source was compiled, but no cleanup invocation was executed. The external verifier's evidence, quiescence and handle-accounting integration remains required.

`common/reader.hpp` and `qualification/native-wire.mjs` require wire v4 and reject older, partial or extra frames. Raw decoder results remain `UNAUTHENTICATED_NATIVE_OBSERVATION`; the private bridge's required-fact gate must also pass before any component observation can be accepted. Neither path grants paid or platform authority. The launch decoder similarly returns metadata only. Native IPC v2 endpoint names and controller endpoint v1 describe their separate transport interfaces, not acceptance of old collector frames.

QI Completion A additionally retains duplicate kernel objects across paired handle samples, checks inherited duplicates against actual read-only file access/object identity, rejects all other inherited handle classes, reopens the child's token and repeats handle checks immediately before release. Its supported restricted launcher token profile permits only `SeChangeNotifyPrivilege`; other privileges, including disabled-but-enableable ones, block. This conservative subset does not qualify representative developer/service roles. Sampled module and handle checks remain insufficient for complete lifetime and execution closure.

## Native security review limits

QI Completion A2 adds composite-access fact 8, with separate primary/effective DAC, MIC, parent DELETE_CHILD/LIST_DIRECTORY, owner/OWNER RIGHTS, active/potential privilege masks and explicit unresolved flags. Both decoders check token policy/integrity, descriptor/mandatory-label, parent masks, arithmetic and non-impersonating equality. This is a bounded native assessment, not complete operation/lifetime proof. Collector v3 is rejected. Legacy observer/event v3 remains a separate regression fixture; the native B2 observer uses `common/observation-protocol.h` B/v2 and rejects B/v1 and legacy frames as current evidence. H10 registrations are unaffected by this private native dialect version.

The machine bootstrap format is now version 2. The launcher controller request/response format is version 2 and requires a fixed persistence-contract identity, stable durable-consumption reference and an independently signed P-256 release receipt bound to the exact fresh request, fixed verifier generation/image/token, phase and monotonic sequence interval. The private signing key is never provisioned by this package. The receipt still carries opaque runtime/lifetime/coverage references; their contents are not yet independently resolved. Consequently **the fixed-role launcher is blocked before controller redemption or child creation in this build**, with no caller/configuration override. Previously received external consumed tickets are not reset. The suspended launch code is retained for completion but is unreachable through the public entry.

`common/storage-profile.hpp` defines and tests a bounded signed physical/VM component package, required component/source classifications, bindings and local volume/cache/filter anchors. It is **not integrated into bootstrap, collector wire or JS acceptance**, and does not yet resolve complete topology, host backing or persistence documentation. Its validation functions do not grant any capability. It is an integration contract, not a completed storage collector.

Remaining implementation work is explicit: full typed storage acquisition/translation; operation-complete effective-right composition; continuous retained/inherited-handle object provenance; complete runtime/JS/DLL/environment closure; complete approved-role semantics; independently verified release coverage and persisted ticket evidence. QI-04–QI-08 producers/services were not implemented by A2. No successful full collector or launcher acceptance is claimed.

Fixed count/length bounds, checked arithmetic, RAII handles and bounded output are implemented. Native checks and AddressSanitizer exercise decoders, malformed bootstrap/launch/cleanup contracts, invalid handles and a nonprivileged process-state fixture. They do not execute protected collector queries, fixed-role launch, mutual TLS, destructive cleanup, ETW or kernel callbacks and cannot replace Application Verifier, static driver analysis or a separately authorized component laboratory.

The service stream decoder rejects malformed records, gaps/replay, mismatched pre/post fields, incomplete drain and unobserved/lost ETW counters with a persistent failure latch. Its caller-supplied synthetic fixtures do not authenticate real process/image/token or device provenance; the service endpoint remains incomplete.

Collector `AccessCheck` output alone is not the complete Windows effective-rights oracle. Protected immutable code/configuration/process bindings must be independently established before interpreting such observations.

The minifilter skips unsafe identity queries and marks capture incomplete when the current context is unsuitable. Microsoft requires PASSIVE_LEVEL, enabled special APCs and no non-null top-level IRP for [FltQueryInformationFile](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/fltkernel/nf-fltkernel-fltqueryinformationfile). [Post-operation callbacks](https://learn.microsoft.com/en-us/windows-hardware/drivers/ifs/ensuring-that-completion-processing-is-performed-at-safe-irql) may run at DISPATCH_LEVEL; the current source has not been proven race-safe under those conditions. Missing observations remain BLOCKED.
